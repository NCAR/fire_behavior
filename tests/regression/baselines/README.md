# Regression baselines

Normal GitHub checks use [github-pr/](github-pr/README.md), covering
all 36 PR-suite runs, including NUOPC and ESMX hybrid terrain cases. Maria
Frediani requested this extension on 2026-10-14. It was generated by GitHub
run `38648160726` with GNU Strict builds and reviewed against the previous
reference and the corresponding MPI outputs.

The directory contains 111 files: 72 NetCDF outputs, 36 settings files, and
three supporting files (`reference.json`, `environment.txt`, and `README.md`).

There is one current baseline. Strict selects `github-pr` by default for every
parallel configuration; separate OpenMP or hybrid reference directories are not
needed. Earlier baseline versions remain available in Git history.
Use `--reference` to override it or `--no-reference` to disable it with a warning.
There is no automatic fallback for a missing case.

Use the manual workflow's `create_reference` input to build all four GNU Strict
configurations and generate an unapproved candidate after the PR suite passes.
Download the candidate artifact and review its NetCDF fields, scientific settings,
coverage, source revision, environment, and cross-execution comparison reports.

Each reference contains `reference.json`, one `settings.json` per named execution,
and the expected NetCDF output files. Keep the environment record and a README
with the authorizing reviewer, date, source revision, and workflow run URL.
Only after explicit authorization and review may `approval` be changed to
`approved` and the reference committed. The final PR workflow must then pass
against those files. Normal checks never generate or refresh a reference.

Do not edit data to make a comparison pass. Generate future candidates in a
separate directory, review and approve them, then replace the current `github-pr`
contents in a commit. Git history preserves earlier versions. Keep the stable
reference path so build commands and documentation do not change with each update.
